# Аналитика Jira для лабораторной работы 4

Подробная инструкция находится уровнем выше: `Туториал_ЛР4.md`.
Это приложение для **Jira Cloud**, в том числе учебного проекта HELP.
Для Apache Jira Server нужен другой API-клиент; простой заменой URL это приложение не адаптируется.

Требуется Python 3.11 или новее. Из папки исходного проекта в PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m jira_analytics --fixture tests\fixture.json --output output-demo
```

Локальный набор искусственный, изображения маркируются ДЕМО. Он не доказывает подключение к Jira.

Для реальной выгрузки настройте `config.toml`, затем задайте переменные в текущем PowerShell:

```powershell
$env:JIRA_EMAIL = Read-Host 'Email Atlassian'
$taskToken = Read-Host 'API token' -AsSecureString
$env:JIRA_API_TOKEN = [System.Net.NetworkCredential]::new('', $taskToken).Password
.\start.cmd --output output-live
```

Токен без scopes работает с адресом сайта. Scoped token требует URL
`https://api.atlassian.com/ex/jira/CLOUD_ID` и разрешений чтения выбранных ресурсов.
Токен не записывается в конфигурацию, код или журнал.

Готовые результаты: `output-live\index.html`, PNG, `summary.json`, `raw_issues.json`, `daily.csv`, `run.log`.
Для времени используются только сейчас закрытые задачи. Дата закрытия — последний переход в
завершающий статус, при отсутствии такого события — `resolutiondate`. `updated` не используется.
При возврате в работу учитывается весь период до последнего закрытия, включая предыдущие
закрытые интервалы. Гистограммы статусов включают задачи, посетившие соответствующий статус.
`timespent` — суммарные зарегистрированные трудозатраты всех участников на задачу; неизвестные
значения пропускаются и подсчитываются отдельно. Это не прошедшее календарное время.
Графики дней, пользователей и серьезности используют всю выбранную JQL совокупность.
Пользователи ранжируются по объединению задач двух ролей, а столбцы показывают роли отдельно.
Текущее назначение/репортер не заменяются историческими владельцами.

По умолчанию график серьезности использует `priority`. Приоритет и серьезность — разные понятия.
Для строгого соответствия формулировке задания создайте одиночное поле «Степень серьезности»
и укажите его ID в `severity_field`. Инструкция содержит оба варианта.

Сборка из исходников:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_release.ps1
```

Скрипт запускает тесты, собирает wheel и ZIP в `dist`. Это Python-дистрибутив, а не автономный EXE.
`config.toml`, `start.cmd`, этот README и wheel включаются в ZIP. Исходники хранятся отдельно в Git.

Установка из распакованного ZIP на другой машине:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\jira_lab4_analytics-1.0.0-py3-none-any.whl
```

Затем настройте конфигурацию и переменные авторизации и выполните `start.cmd`.
Для установки matplotlib нужен интернет. Секреты в ZIP не входят.

Проверки: модульные расчеты и транспорт клиента плюс два интеграционных теста:
полный конвейер CLI → JSON/CSV/PNG/HTML на фикстуре и постраничный клиент → аналитика.
Сетевые ответы в тестах заменены управляемыми данными. Реальное подключение проверяется отдельным
запуском без `--fixture` и сверкой выбранных задач в интерфейсе Jira.
